# Prinny Multi-AI Team Policy

## 프로젝트 우선순위

1. Prinny 1 완성
2. Prinny 2 호환성 및 자료 조사
3. PSP 종합 한글화 도구

현재 활성 쓰기 작업은 Prinny 1만 허용한다.
Prinny 2와 PSP 종합 도구는 Prinny 1의 주요 단계가 끝날 때까지 읽기·분석만 수행한다.

## 역할

- Codex: 메인 구현 AI이자 유일한 코드 작성자
- Claude: 사용자 지시에 따라 현재 비활성
- Gemini: 사용자 지시에 따라 현재 비활성
- 사용자: 번역 문구 변경과 위험 작업의 최종 승인자. 테스트 ISO 생성은
  2026-08-01 사용자 지시에 따라 철회 전까지 자동 승인 상태다.

Claude와 Gemini는 사용자가 다시 활성화하기 전까지 호출하거나 필수 게이트로
요구하지 않는다. Codex는 쓰기 전과 쓰기 후에 같은 검사를 새 입력에서 각각
재계산하고 결과를 별도 보고서로 남긴다.

참고 자료 지정만으로 자동 승인된 것으로 보지 않는다.

## Prinny 1 필수 게이트

다음 게이트를 순서대로 통과하지 않은 산출물은 다음 단계로 승격하지 않는다.
우회 옵션이나 강제 성공 경로를 만들지 않는다.

1. 범위: 화면 증상, 대상 장면, 자원, 실행 파일을 서로 구분한다.
2. 출처: 원본, 부모 빌드, 번역, 코드맵, 폰트의 경로·크기·해시를 기록한다.
3. 왕복: 추출 후 무수정 재조립이 바이트 동일하거나 차이가 설명되어야 한다.
4. 폰트: 라이선스, 타일 크기, bpp, 글리프 수, 매핑, 실제 가독성을 검증한다.
5. 인코딩: 모든 적용 문자열을 encode/decode 왕복하고 런타임 글리프와 연결한다.
6. 번역: 용어 일관성, 화자 귀속, 캐릭터 말투, 미번역, 중복 의미를 검사한다.
7. 레이아웃: 슬롯 용량, 표시 폭, 줄 수, 제어코드, 종료 바이트, 패딩을 검사한다.
8. Expected Write: 대상·오프셋·before·after·경계·허용 변경 범위를 확정한다.
9. 봉인: 실제 빌드 입력 목록과 해시를 manifest로 고정하고, 외부 검토자가
   비활성인 동안에는 Codex가 독립된 사전·사후 검사 경로로 이중 검증한다.
10. 빌드: 쓰기 직전에 2~9를 새로 계산하고 하나라도 다르면 실패한다.
11. 런타임: 동일 장면 전후 화면, 입력 순서, 세이브 상태, 빌드 해시를 묶는다.
12. 배포: 사용자 확인과 회귀 통과 뒤에 패치만 배포 후보로 승격한다.

## 번역 정책

- 캐릭터별 말투와 기존 번역 스타일을 보존한다.
- 대사를 자동으로 윤문하거나 현대화하지 않는다.
- 한국어 문구를 임의 생성하거나 교체하지 않는다.
- 자동 허용 수정은 인코딩, 글리프, 제어코드, 포인터, 종료 바이트,
  패딩, 슬롯 초과, 미번역 일본어 같은 기계적 문제로 한정한다.
- 문체 변경이 필요하면 검토 항목으로만 기록한다.

## ISO 및 바이너리 안전 정책

- inputs/game.iso와 inputs/game2.iso는 읽기 전용이다.
- 원본 및 기존 ISO를 수정, 삭제, 이동, 덮어쓰기하지 않는다.
- 테스트 ISO는 2026-08-01 사용자의 자동 승인 지시에 따라 필수 게이트와 독립
  검토 PASS 뒤 별도 확인 없이 생성할 수 있다. 배포용 최종 ISO 또는 패치 승격,
  원본 변경과 위험 작업은 이 자동 승인에 포함되지 않는다.
- Expected Write가 확정되지 않은 후보를 적용하지 않는다.
- 원본 바이트, 대상 파일, 오프셋, 문자열 경계, 종료 바이트, 패딩,
  슬롯 용량을 모두 검증한다.
- 허용 범위 밖에서 1바이트라도 변경되면 실패 처리한다.
- 패치 전후 파일 크기와 해시를 기록한다.
- PPSSPP, 브라우저, 별도 터미널을 자동 실행하지 않는다.

## 작업 방식

- 관련 코드와 최신 보고서를 먼저 읽는다.
- 수정 전 원인, 수정 대상, 변경 범위, 검증 계획을 정리한다.
- 계획만 출력하고 멈추지 말고 안전한 로컬 구현과 검증까지 수행한다.
- 오류가 발생하면 원인을 분석하고 안전한 범위에서 수정 후 재검증한다.
- 추측으로 후보를 패치 가능 상태로 승격하지 않는다.
- 기존 사용자 변경을 되돌리지 않는다.
- git reset --hard, git clean, rm -rf, force push를 사용하지 않는다.
- ISO, 게임 데이터, workspace, reports, build, 로그, 키를 Git에 추가하지 않는다.
- 변경 후 관련 테스트, py_compile, git diff, git status를 실행한다.
- 테스트 ISO는 자동 승인 범위에서 생성하고 구조·런타임 검증까지 계속한다.

## GitHub 체크포인트

공식 원격 저장소:
https://github.com/sizz1214-lang/prinnyk

독립 기능 구현과 검증, 중요 오류 수정과 회귀 검증, 또는 x.0/x.5 버전
목표가 완료되면 Git 체크포인트 대상이다.

체크포인트 조건:

- 활성 외부 검토자가 있으면 최종 검토에 BLOCKER가 없다.
- 외부 검토자가 없으면 봉인 manifest와 빌더의 사전·사후 재검증이 모두 통과한다.
- 관련 테스트가 통과한다.
- 금지 파일이 변경 목록에 없다.
- origin이 공식 원격 저장소와 일치한다.
- 로컬 커밋 성공과 원격 push 성공을 구분해 보고한다.
- x.0 또는 x.5 버전은 동일 버전 태그를 생성하고 push한다.
- 기존 태그는 삭제하거나 덮어쓰지 않는다.

## 검토 판정 형식

각 검토자는 답변 마지막에 정확히 한 줄을 출력한다.

FINAL_VERDICT: PASS
FINAL_VERDICT: WARNING
FINAL_VERDICT: BLOCKER

BLOCKER는 패치, 체크포인트, push를 중단한다.
WARNING은 근거와 영향 범위를 반드시 기록한다.
