# Prinny 1 한글 패치 1순위 규칙 V2

작성일: 2026-08-01

## 목적

Prinny 1을 최우선으로 완성하되, 화면상 일부 정상화를 전체 성공으로 오인하지 않고
재현 가능한 패치와 런타임 증거를 함께 만든다. 이 문서는 외부 참고 자료의 방법론을
PSP/Prinny 1 구조에 맞게 채택한 로컬 실행 규칙이다.

## 참고 자료별 채택 범위

| 자료 | Prinny 1에 채택하는 기준 | 바로 전용하지 않는 부분 |
|---|---|---|
| create-retro-game-kr-patch | 조사→엔진 분석→폰트/인코딩→재삽입→런타임 검증의 전체 흐름 | PSP에 검증되지 않은 타 플랫폼 팁 |
| emucap | 빌드 해시, 세이브 상태, 입력 순서, 화면을 한 실험 단위로 기록 | 도구 설치와 에뮬레이터 자동 실행 |
| create-kr-patch-template | 저작 자산 분리, source lineage, Expected Write, 재현 빌드, runtime evidence | 템플릿 구조의 기계적 복제 |
| Font Share | 후보 탐색과 원본 라이선스 확인의 출발점 | 사이트 등재만으로 재배포·수정 가능 판정 |
| hanpatch | fail-closed 게이트, 산출물에서 재도출하는 검사, 봉인 manifest, 독립 QA | 3DS 전용 어댑터와 파일 형식 |
| hancharacter | 화자 귀속, LOSS/INVENTION 방지, 번역 권한과 게이트 판정 분리 | 근거 없는 말투 계약 자동 봉인 |

## 작업 우선순위

1. 사용자 화면에서 재현된 Prinny 1 손상과 진행 차단 문제
2. 같은 원인의 전체 자원 범위 조사와 기계적 수정 계획
3. 미번역 UI의 자원·포인터·용량 확정
4. 글꼴 가독성, 누락 글리프, 매핑 충돌 회귀
5. 번역 문구 검토가 필요한 항목의 승인 큐
6. Prinny 2 읽기·분석
7. PSP 종합 도구 확장

한 화면만 고치는 국소 패치는 허용하지만, 같은 원인이 다른 위치에도 존재하는지 먼저
검색한다. 전체 범위를 모르면 국소 수정임을 명시하고 배포 완료로 보고하지 않는다.

## 화면 문제 처리 규칙

1. 원본 사진은 변경하지 않고 파일 해시와 관찰 사실을 기록한다.
2. 화면 판독 문구는 `관찰`, 자원 연결은 `후보`, 바이트 일치 뒤에는 `확정`으로 구분한다.
3. 깨진 한글, ASCII/한자 혼입, 검은 사각형은 코드맵뿐 아니라 바이트 위상,
   문자열 시작 위치, 제어코드, 종료 바이트를 함께 검사한다.
4. 일본어 잔존은 START 자원, BOOT/EBOOT 실행 파일, 이미지 UI를 구분한다.
5. 번역이 이미 존재하면 문구를 새로 만들지 않고 인코딩·레이아웃만 교정한다.
6. 문구가 없거나 슬롯을 맞추려면 뜻·말투 변경 없이 해결 가능한지 먼저 판정하고,
   불가능하면 사용자 승인 큐로 보낸다.

## 폰트·인코딩 규칙

- 폰트 후보마다 출처 URL, 파일 해시, 버전, 제작자, 라이선스 원문, 수정·임베딩·
  재배포 허용 여부를 기록한다.
- 타일 크기, bpp, baseline, advance, 글리프 인덱스, 문자 코드, alias를 기록한다.
- 정적 미리보기는 런타임 통과가 아니다. 최소한 이름창, 대사창, 고정폭 설명창,
  숫자·기호 혼합 문장을 실제 렌더러에서 확인한다.
- 한글 2바이트 스트림에 ASCII 1바이트가 섞일 때는 위치별 위상 변화를 검사한다.
  전역 advance 변경은 국소 문자열 정렬 문제의 기본 해결책으로 사용하지 않는다.
- 사용 문자 집합과 폰트 글리프 집합은 양방향 포함 관계와 충돌 0건을 증명한다.

## 빌드·검증 규칙

- 원본 ISO와 검증된 기준 ISO는 항상 읽기 전용이다.
- 새 ISO는 사용자 승인 뒤 별도 경로에만 만든다.
- 빌더는 Expected Write 적용 직전에 부모 해시와 before 바이트를 다시 읽는다.
- 실제 변경 바이트는 선언된 합집합 안에만 있어야 하며, 0건도 실패다.
- 압축 자원은 재압축 후 재추출하여 논리 자원과 Expected Write를 다시 검증한다.
- 빌드 성공, 부팅 성공, 목표 장면 성공, 인접 장면 회귀 성공을 별도 상태로 기록한다.
- PPSSPP 증거에는 ISO 해시, PPSSPP 버전, 그래픽 설정, 세이브 상태 또는 입력 순서,
  캡처 해시와 사용자 판정을 포함한다.

## 외부 xdelta 참고 규칙

- 정확한 원본 ISO가 없는 xdelta 강제 해제본은 빌드 기반이나 배포 후보가 아니라
  자원 범위 확인용 참고 자료로만 사용한다.
- 후보 바이트를 직접 가져오지 않고 원본·현재판·후보의 동일 자원과 동일 슬롯을
  비교해 `현재판 보존`, `사용자 번역 검토`, `폰트 결합`, `후순위 이미지`로 분류한다.
- 2026-07-29 후보의 QA 텍스트 슬롯 4,110개 중 4,070개는 현재판과 후보가 모두
  번역됐으나 인코딩 또는 문구가 다르고, 40개는 현재판 `PrinnyName.dat`에만 있는
  수정이다. 후보만 번역된 기존 QA 슬롯은 0개이므로 후보 텍스트를 직접 이식하지 않는다.
- 후보 BOOT 변경은 현재 난이도 문자열 블록 5개의 대상 위치를 교차 확인하는 참고
  근거로 사용한다. 현재 사용자 번역과 포인터 재배치 9개 Expected Write를 우선한다.
- 후보의 `F0 40~F5 6E` 987개 매핑, font.fnt, font.txp와 후보 텍스트는 하나의
  결합된 체계로 취급하고 현재 980자 코드맵과 혼합하지 않는다.
- 후보의 `ANIME.DAT`, `BG.DAT`, `anime00.dat`, `number.txp` 변경은 내부 이미지
  위치 탐색 자료로 보존하되 게임 내부 텍스트 완료 전에는 적용하지 않는다.

## 현재 사진 묶음의 적용 판정

- 테스트0~17: 기존 18개 이슈와 동일하며 V7.14.3에서 한 건만 런타임 해결이 확정됐다.
- 테스트18: `프리니코프` 대사에 별도 깨짐이 남아 있어 Demo00.dat 후보 연결이 필요하다.
- 테스트19~24: StageInfo00.dat의 여섯 지역 설명에서 ASCII 공백·문장부호·영숫자가
  2바이트 표시 위상을 깨는 현상이 반복된다. 기존 번역을 유지한 기계적 전각화 후보를
  전체 범위에서 검증한다.
- 우측 지역 목록, 난이도, 튜토리얼, HUD, 결과 화면 일본어는 별도 실행 파일/UI
  자원 트랙으로 유지한다. 승인 번역과 포인터·용량 확정 전에는 쓰지 않는다.
