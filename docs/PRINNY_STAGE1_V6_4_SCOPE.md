# Prinny Stage 1 V6.4

## 원인

V6.3 보고서의 `실제 변경 0개 영역`은 14개 대상 바이트가 이미 V6.3 계획과 같았다는 뜻이다. 따라서 V6.3은 실질적인 수정이 아니었다.

확인된 문제 문자열은 한글 코드(2바이트) 사이에 ASCII 공백, 쉼표, 마침표, 물음표, 느낌표, 물결표, 숫자(1바이트)를 섞고 있었다. 문제 화면에서 깨짐은 첫 1바이트 문자 뒤부터 시작하는 패턴과 일치한다.

V6.4는 문장 의미와 캐릭터 말투를 재번역하지 않고 표시 코드를 2바이트 전각 코드로 정규화한다.

## 기계적 최소 조정

- `응원하고 있슴다!!` → `응원하고있슴다!`
  - 18바이트 슬롯에서 2바이트 정렬을 지키기 위한 공백 제거와 느낌표 1개 축소
- `재료를 손에 넣을 필요가 있슴다.` → `재료를 손에 넣을 필요가 있슴다`
  - 34바이트 슬롯에서 2바이트 정렬을 지키기 위한 마지막 마침표 제거

그 외 대사 문구는 그대로 유지한다.
